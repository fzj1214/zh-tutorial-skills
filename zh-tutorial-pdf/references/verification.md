# 数值可追溯与交叉验证

教程里的数字被读者复算却对不上，是最伤可信度的错误 —— 比文字写得平淡严重得多。

## 1. 文档里的数字必须来自程序

程序输出一律排成**脚本生成的表格**（见 `latex.md`「程序输出：排成表格」），不再手抄，
也不再原样贴 stdout。机器比对相应分三道，模板见 `../assets/verify_numbers.py`：

| 检查 | 做法 | 防的是什么 |
|---|---|---|
| 表格可重建 | 正文 `\input` 的每张 `tables/<id>.tex`，都要能由 `examples/out/tables/<id>.json` **逐字节重新生成** | 有人（包括你）手改了生成的表格 |
| 正文数字可追溯 | 正文句子、表题、表注里带小数的数字，逐个去运行数据里找：逐字相同，或按它的精度四舍五入后相同 | 凭印象写进正文的数、抄错的数、过期的数 |
| 残留的逐字输出 | 还留着的 `minted{text}`（报错、日志）逐行 grep 真实 stdout | 报错信息被"整理"过 |

找不到来源的数字，要么是编的，要么是合法例外 —— 写进白名单，**每一条注明来源**
（"arXiv 编号，不是测量值"、"第八章讲的正是这个编造的数"）。不许为了让检查通过而扩白名单。

表题、表注里手写的参数（$\Delta t=2\times10^{-6}$、系数 $0.15$）同样要核对。实测它们
第一次跑就被抓出两处：脚本根本没把这两个参数打印出来，数字无从核对。修法是让脚本把
设定参数打印到 stdout —— 运行记录里本来就该有。

**核对器本身要用反例测一次。** 从没报过错的检查器证明不了任何事（实测一个版面检查器
"全部通过"，其实它根本没扫刻度标签）。做法：往正文里塞一个编的数、手改生成表格里的一格，
确认两处都被报出来、返回码非零，再复原。

**实测抓到过**：

- 手算 $f(-2.5)=-0.625$ 写进表格，程序实际输出 $-0.125$。纯手算的数字最危险，
  因为它从不经过任何检验。
- 一张物性插值表凭印象写了后半截，写出 $\mu=-0.0727$ 的负黏度，还为它补了一整个解释框；
  真实输出里 $\mu$ 从 $10$ 平滑降到 $0$，根本没有负值。**解释写得越顺，越难被自己发现。**
- 正文写"四个比值都是 $0.999984$"，改成表格重跑后发现只有第一行是。
- 作图脚本里还留着一份手抄的数组 —— 那是第二份手抄，数据改了图不会跟着变。
  作图数据一律从表格 JSON 读。

旧式 stdout 逐行比对（仍适用于残留的逐字输出块）：

```python
import io, re
doc  = io.open('doc/report.typ', encoding='utf-8').read()     # 或 .tex / .md
outs = ''.join(io.open(f, encoding='utf-8').read()
               for f in ['/tmp/out1.txt', '/tmp/out2.txt'])    # 程序真实输出

bad = []
for block in re.findall(r'```(?:\w+)?\n(.*?)```', doc, re.S):
    for line in block.splitlines():
        t = line.strip()
        if not t or t.startswith(('cd ', '...')):      # 跳过命令行与省略号
            continue
        if t not in outs:
            bad.append(t)
print(f'未匹配 {len(bad)} 行')
```

## 2. 手算只用来形成预期

手算与程序冲突时，**先假设手算错了**。核实后一律以程序输出为准，
并顺手检查程序是否真的算的是你以为的那个量。

## 3. 每个关键结论配一条独立交叉验证

关键在于验证路径要和主计算**不同源**，否则只是把同一个错误算了两遍。可用的路径：

| 手段 | 例子 |
|---|---|
| 更高精度重算 | 用 `decimal` / `mpmath` 做 40 位迭代，核对双精度结果的有效位 |
| 解析解 / 闭式解 | 能解析求解的特例，数值必须命中 |
| 守恒量与恒等式 | 三次方程根与系数的关系：三根之和为 0、之积为 $-3$ |
| 理论预言 vs 实测 | 梯度下降稳定性上界 $a<2/\lambda_{max}=0.2918$，实测 $a=0.29$ 收敛、$0.30$ 发散 |
| 多实现互校 | 同一算法的 Python / C / Fortran 版本必须给出完全相同的结果 |
| 量纲与极限 | 参数取 0 或 ∞ 时是否退化到已知结论 |

理论值与实测值精确对上的那一刻，是教程里最有说服力的段落 —— 值得专门写一段。

## 4. 改完代码要跑回归

给算法加"改进"时极易引入新 bug。**实测发生过**：给求根法加浮点停滞判据
`x == x_prev`，结果混合法首步若走二分步就会误判收敛（初始值本就是区间中点，
二分一次算出同一个点），1 步返回一个非根并宣称"正确"。

这类 bug 的特征是**只在特定分支触发**，主结果毫发无伤，因而极易漏网。所以：

- 每次改算法后，把**全部**结果重跑一遍与改动前对比，不能只看主结果
- 边界/退化输入要专门跑（首步、零导数、区间退化、空输入）
- 状态标志只承担一个语义（见 `figures.md` 的 `diverges` 例子）
- 修掉的 bug 留一个开关复现它（`buggy_dt=True`、`--naive`），让它变成回归测试，
  也让正文里"第一版得到的是……"那些数字可以重跑出来，而不是凭记忆转述

## 5. 报告偏差，不要掩盖

数值结果与解析解有偏差时，把偏差量级写出来并解释它的来源：

> 坐标偏差约 $10^{-10}$，与收敛判据 $|\nabla g|<10^{-10}$ 相称：极小点附近
> $|\nabla g|\approx\lambda|\Delta x|$，故坐标精度与梯度判据同量级。

解释得清楚，偏差就是能力的体现；含糊带过，读者只会当你没算对。

双精度的硬限制也要讲明白：要求 14 位小数时，$x\approx1.83$ 处相邻浮点数间距已是
$\varepsilon|x|\approx4.1\times10^{-16}$，容差应取 `max(tol, eps*|x|)`，
否则迭代会在最后 1 个 ulp 上振荡而永不停机。
