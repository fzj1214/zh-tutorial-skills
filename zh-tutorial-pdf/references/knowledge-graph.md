# 读者知识图：8 题定位边界

配合 `SKILL.md` §0。目的是把「哪些概念要展开讲」从拍脑袋变成**可测的**。

## 前人做到哪了

这套东西 1985 年就形式化了，叫**知识空间论**（Doignon & Falmagne）。
「懂 A 才能懂 B」在那边叫 **surmise relation** `A ≼ B`，整个结构是 AND/OR 图的变体。
工业实现是 **ALEKS**：

| | |
|---|---|
| 一门课的 item 数 | 400 ~ 500 |
| 314 个 item 的合法状态数 | ~10²³（子集数是 2³¹⁴ ≈ 10⁹⁴） |
| 定位一个学生需要 | **25 ~ 30 题** |

依赖结构把 10⁹⁴ 压到 10²³ —— **这就是本方法全部的威力来源**。

**但不要试图建全局知识图谱。** Cyc 从 1984 年手工编本体，到 2002 年烧掉 6000 万美元、
600 人年，赌的那个「知道得多了就能自己学」的临界点从未到达。
ALEKS 之所以成功，恰恰因为**不穷尽**：死死圈在窄领域的几百个 item 里。

更根本的一条：**先修关系不是客观的**。同一主题走不同教学路线就是不同的图，
两条路都对。没有唯一正确的图可供穷尽。所以——

> **每份文档一张局部图，从根节点懒展开，只展开读者说不懂的那一支。**

我们只有一个读者、十几个概念，**8 题足够**；ALEKS 要 25~30 题是因为它要在 10²³ 个
状态里定位，还要建可复用的群体模型。我们不需要。

## 关键决定：节点一律写成「可观察的检查」

**不要分「概念节点」和「任务节点」。** KST 的 domain 是 *problem types*，
知识状态的定义是「该学生**能解**的题目全集」—— 它从一开始就选了任务那一侧，
因为**理解不可观察，表现可观察**。

所以学术内容也要落到可观察的动作上：

| 领域 | 节点写法（✗ → ✓） |
|---|---|
| 数学 / 理论 | ✗ 懂线性代数 → ✓ 看到 $J^\top M J$ 能说出它在做什么 |
| 物理 / 力学 | ✗ 学过刚体动力学 → ✓ 能一句话说清 $M$ 和标量 $m$ 的关系 |
| 数值方法 | ✗ 熟悉数值分析 → ✓ 「二阶收敛」是熟悉的说法 |
| 软件 / 工程 | ✗ 会用 Docker → ✓ 跑过 `docker build` 并知道输出长什么样 |

工程任务有一条额外注意：**能做 ≠ 懂**。所以工程节点的探针要问**产物或现象**
（"你见过它失败时报什么错吗"），不要问"你理解 X 吗"。

KST 用 BLIM（Falmagne & Doignon 1988）在观测上加 β（粗心做错）和 η（蒙对）两个
误差参数来处理这件事。我们没有统计样本，替代办法是：**答案与图冲突时相信图被证伪**（见下）。

## 文件格式

一个 `reader.yml`，人可读、可 diff：

```yaml
reader: <名字或 anon>
updated: 2026-09-21
root: MuJoCo 约束求解流水线      # 这份文档要讲清楚的那个东西

# A 很熟 / B 见过说不准 / C 完全不懂 / '?' 还没问
known:
  雅可比: A
  矩阵乘法: A
  质量矩阵: C
  互补条件: C
  线性插值: C
  惯量张量: '?'      # 引号不能省，见下

# 依赖边：叶 -> 根。这是【我的猜测】，读者的回答可以推翻它
needs:
  约束求解流水线: [质量矩阵, 雅可比, 互补条件, 凸优化]
  质量矩阵: [惯量张量, 广义坐标, 动能]
  互补条件: [不等式约束, 内积为零的几何含义]
```

> **写完必须验它能被解析。** 裸 `?` 是 YAML 的复合键标记，`惯量张量: ?` 会让
> **整个文件**报 `ScannerError: mapping keys are not allowed here` —— 不是只坏那一行。
> 表示「还没问」必须写成 `'?'`。
>
> 下表是拿 PyYAML 逐个试出来的（`k: <值>`），别凭印象：
>
> | 裸值 | 结果 |
> |---|---|
> | `?` `-` `:` `@` `` ` `` `%` | 报错 `ScannerError` |
> | `*x` | 报错 `ComposerError`（当成别名去找锚点） |
> | `!x` | 报错 `ConstructorError`（当成标签） |
> | `{x` | 报错 `ParserError` |
> | `a #x` | **不报错，静默变成 `a`** —— 后面被当注释吃掉 |
> | `&x` | 不报错，得到 `None`（锚点挂空值，合法） |
> | `a：b` | 不报错（全角冒号没事，半角才有事） |
>
> 最后那个 `#` 尤其阴：它不报错，只是悄悄把值截短。
>
> 这一条是实测踩出来的：本技能自己的示例模板长期写着裸 `?`，照抄的人全都中招，
> 而且要到第一次真去读这个文件才会发现。写完加一句
> `python -c "import yaml; yaml.safe_load(open('reader.yml'))"`，一秒钟的事。
> **你生成的任何配置文件都适用这条。**

**边是假设，不是事实。** KST 公认的短板就是先修序得靠人手工建、且难以自动修正。
我们的办法是把每条边当成可证伪的假设 —— 成本几乎为零，见下面的诊断 2。

## 算法：预算 8 题，A 剪枝 C 展开

```
根 = 这份文档要讲清楚的那个东西
展开一层 → 根的直接依赖（5~8 个，别多）
fringe = 其中 status 为 ? 的节点

第 1 轮：问 5 题  ← 从 fringe 里挑「被依赖次数最多」的（枢纽节点，剪枝收益最大）
   A → 标 A，【它依赖的一切一并视为 A】，整条支线不再问
   B → 标 B，不展开
   C → 标 C，展开它的 needs，新节点进 fringe

第 2 轮：问 3 题  ← 只问上一轮答 C 的那些节点新展开出来的子节点

到此为止。总共 8 题，不再追加。
```

「A → 下游全部视为 A」就是 KST 的**下闭性**（知识状态对先修封闭）。
这是成批剪枝，也是 8 题能覆盖 20~40 个节点的原因。

**为什么分两轮而不是一次问 8 题？** 因为第二层问什么**取决于第一层的答案** ——
不分轮就退化成非自适应测验，等于放弃了这套方法唯一的优势。
ALEKS 是一题一自适应；两轮是对话场景下的折中。

**提问格式**（一次列全，让读者一口气答完）：

```
1. 看到 J^T M J 这种写法，你能直接说出它在做什么吗？
   A 能，很熟    B 见过，说不太准    C 完全不懂
```

明确告诉读者：**C 是最有价值的回答。**

## 三个白送的诊断

图建起来之后，不用额外提问就能读出三件事：

**1. 起点过高** —— 根的直接依赖里 C 占一半以上
→ 这份文档的起点选错了。要么把根往下挪，要么在开篇明确声明
「本文假设你已掌握 X、Y」，不要闷头往下写。

**2. 边画错了** —— 某节点答 A，但它的先修答 C
→ 你那条依赖边是猜的，现在被证伪了。可能是：真的不需要那个先修、
或者读者高估了自己。**先改图，再问一句确认**，别默默忽略。

**3. 天花板** —— 全是 A
→ 这份文档对这个读者太浅。直接写紧凑版，把篇幅让给他真正不懂的东西。

## 什么时候停止向下展开

**切断位置是关于读者的判断，不是关于知识的性质。** 图向下无界
（质量矩阵 ← 惯量张量 ← 积分 ← 极限 ← 实数 ← 集合论 ← …），必须自己切。

三条实用的停止规则：

- **8 题用完就停。** 硬上限。
- **问出口会冒犯人的，不问。** 对机器人方向的博士生问「你知道什么是矩阵吗」，
  既浪费预算又难堪。这一层直接标 A。
- **fringe 空了就停。**

## 跨文档复用

`reader.yml` **跟着读者走，不跟着项目走**：

```
~/.<agent>/readers/<name>.yml     主副本，下一本教程从这里起步
<项目>/reader.yml                 项目内快照，保证这本书可复现
```

这是复利所在：第二本教程不用从零问起，只问新根节点带出的新分支。
读者说「这段看不懂」时也要回写 —— **那不是报修，是一个观测**。

## 局限（写在前面，免得高估它）

- 图是**我猜的**，不是从数据学的。它只在这次对话里有效，别当成客观知识结构。
- 读者的自评有误差。KST 靠 BLIM 的 β/η 参数统计校正，我们没有样本，
  只能靠诊断 2 做一次性的一致性检查。
- **不要试图跨领域合并这些图。** 那条路通向 Cyc。
