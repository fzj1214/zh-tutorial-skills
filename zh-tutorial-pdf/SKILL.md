# zh-tutorial-pdf

把一份论文 / 教材 / 讲义 / 实验结果，做成一本**中文教程 PDF**。

## 先认清难点在哪

写中文说明文字是模型最不容易出错的部分，**不要把精力放在那里**。真正会翻车的是这几件事，
本技能全部围绕它们：

| 翻车点 | 表现 | 对策 |
|---|---|---|
| 不知道读者卡在哪 | 自以为讲清楚了，读者第三页就停住 | §0 **先做** |
| 编译链没闭环 | 写了一万字交不出 PDF；中文变豆腐块 | §1 |
| 没拿到原始材料 | 全凭记忆复述论文，公式记号与原文对不上 | §2 |
| 讲得抽象 | 通篇符号推导，初学者读完仍不知道数据长什么样 | §5 **最重要** |
| 数字是"编"的 | 正文数值与代码输出对不上，一核就穿 | §6 |
| 图挤成一团 | 文字重叠、箭头含义不明、字被裁掉 | §7 |

## 0. 先问清读者在哪儿

「不要堆砌概念、把初学者不懂的都讲清楚」这条要求**你无法自查**。你已经懂了，
那道坎在你眼里就是平地 —— 这是知识的诅咒，靠"更努力地讲清楚"绕不过去。

**所以动笔前、以及每次大改前，先问 3~5 个问题，把读者的边界测出来。**
这是一个实证步骤，不是客套。

### 怎么出题

1. 通读原始材料，列出这份文档**依赖**的概念（通常 10~20 个）。
2. 挑出**落在边界附近**的 3~5 个。太基础的（什么是矩阵）和文档本身要讲的主题
   都不用问。
3. 每题必须**具体、能一句话回答、直接取自将要出现的内容**。

**问具体的东西，不要问水平。** 人对自己水平的估计极不准，但对"这个式子我看不看得懂"
判断很准。

| 不要这样问 | 改成这样问 |
|---|---|
| 你的线性代数基础如何？ | 看到 $J^\top M J$ 这种写法，你能直接说出它在做什么吗？ |
| 熟悉数值方法吗？ | 「二阶收敛」对你是不是熟悉的说法？ |
| 学过刚体动力学吗？ | 质量矩阵 $M$ 和标量质量 $m$ 的关系，你能一句话说清吗？ |

每题配选项，并明确允许「不懂」：

```
A 能，很熟        B 见过，但说不太准        C 完全不懂
```

**告诉读者「C 是最有价值的回答」。** 一次问完，别搞成二十题的摸底考。

### 拿到答案之后怎么用

| 回答 | 做法 |
|---|---|
| **C 完全不懂** | 给**独立小节** + §5 的真实数字走一遍。只塞一个「给初学者」框是不够的 |
| **B 见过说不准** | 一个「给初学者」框 + 一个具体数字的例子 |
| **A 很熟** | 正常使用；首次出现仍给中英对照 |

把问答结果**写进项目**（`README.md` 或 `parts/p0_intro.tex` 开头），
后面每次修改都按这条基线判断，不要凭当时的感觉。

### 改教程时同样适用

读者说「这段看不懂」时，**那不是一次报修，是一个数据点**：

1. 先补这一处；
2. **再扫一遍全文有没有同一类的坎** —— 同一个知识缺口通常在文档里出现好几处；
3. 把这个概念补进基线记录。

只修被点名的那一段，下一页还会卡住。

> **实测**：一次 MuJoCo 教程任务里，册子交付之后读者接连问了五个「这个我不懂」——
> 关节四参数、`solimp` 的五个数、$A = JM^{-1}J^\top$、质量矩阵是什么、线性插值是什么。
> 这五个概念**书里全都写了**，但都是按「已经懂的人」的密度写的。
> 写之前花三个问题，这五次追问可以全部避免。

## 1. 先闭环，再写一个字

**动笔前必须先编译出一页测试 PDF**：一行中文 + 一个行间公式 + 一张插图 + 一个代码块。
跑通了后面才是纯写作；跑不通就先解决工具链，别攒了几千字才发现编不出来。

| 情形 | 选择 |
|---|---|
| **默认首选** | **tectonic**。`brew install tectonic`，单二进制、**不需要 sudo**、宏包按需自动下载，完整 LaTeX 生态（TikZ / pgfplots / tcolorbox / algorithm2e / biblatex）都能用。实测 ctex + 中文 + TikZ 一次编译 3.3 秒 |
| 机器已有 TeX Live / MacTeX，或要套既有 `.tex` 模板 | 直接用 **XeLaTeX + ctex** |
| 只想要极简依赖、不需要 LaTeX 宏包生态 | **Typst**，编译以毫秒计，语法现代 |

三种都见 `references/latex.md`（tectonic / XeLaTeX）与 `references/typst.md`。
**MacTeX / BasicTeX 是需要 sudo 的 pkg，agent 装不了 —— 不要在这上面反复尝试，直接上 tectonic。**

字体：中文正文 `Songti SC`、标题 `Heiti SC`、西文 `Libertinus Serif` / `New Computer Modern`、
等宽 `Menlo`。macOS 自带，但**先确认**（`typst fonts` / `fc-list :lang=zh`），不要假设。

## 2. 先把原始材料抓到本地

**在写之前**，把能公开获取的东西全下载下来，教程要靠它们对照着讲，不能凭记忆复述：

- **论文 TeX 源码**（首选）：`curl -L -o src.tar.gz https://arxiv.org/e-print/<id>`，
  解包得到 `.tex` 正文与原始插图。有源码就能逐字引用定义、照搬记号、复用图。
- 没有源码时退而下载 PDF，并抽取文字层。
- **官方实现代码**：作者仓库、`paperswithcode`、HuggingFace。
- **数据集 / 权重 / 配置**：体积可控就下，过大（> 几百 MB）只记录获取方式与校验和。

**下载成功 ≠ 拿到正确的东西。** 拿到后先核对标题、作者、年份、会议，再开始引用 ——
按 ID 抓错论文是很常见的事，而且只有真读了才会发现。

写作时**论文原文与代码实现必须同时摆出来对照**：论文写的公式、代码里真正算的东西、
两者的差异（论文省略的 ε、代码里多出的 dropout、维度顺序不同），正是教程最有价值的部分。
详见 `references/sources.md`。

## 3. 骨架

```
项目/
  main.tex / main.typ   主文件：封面、样式、说明框定义、引入各章
  parts/                正文按节拆开，一节一文件（长文档增量修改的关键）
  figures/              一图一源码 + 产物；make_figures.py 或 fig_xxx.tex
  examples/             §5 的算例脚本：跑出数字并直接生成表格源码
  sources/              §2 下载的论文源码、参考实现、数据（大文件只留说明）
  build.sh              一键：先编图，再编正文
```

## 4. 教学脚手架：彩色说明框

写第一节前就把类型定死，中途新增会前后不一致。同一类内容永远用同一个框，读者靠颜色导航。
现成定义（Typst 与 LaTeX 两版）见 `assets/template.typ` 与 `references/latex.md`：

直觉图像（蓝）· 给初学者（绿）· 推导补全（橙）· 易错点（红）· 历史与背景（灰）·
译注/版本注（紫）· 本节要点（青）· 思考题（棕）

**用哪种框由 §0 的答案决定，不是凭感觉。** 读者答 C 的概念不要只包一个绿框了事 ——
那说明它需要一个独立小节。

改写英文原著：原文公式**保留原编号**（如 (1.17)），自己补的另起一套（如 (补1.3)）；
发现原文印刷错误，正文改正并用译注框注明，不要静默修改。

## 5. 具体化：用真实数字走完整条流程

**这是教程好坏的分水岭，也是本技能最重要的一条。**

解释概念最有效的方式不是更精确的措辞，而是**给出具体数字**：真实的输入、预设好的权重，
把每一步的运算和结果一个矩阵一个向量地写清楚。凡是 §0 里读者答 B 或 C 的概念，
都必须这样落地。

内容复杂时，**贯穿全书用同一个应用案例**，从输入到输出把数值流转完整走一遍 ——
不要每节换一个新例子，连续性才是让人开窍的东西。

要点（完整方法与范例见 `references/worked-examples.md`）：

- 维度取小但**不退化**：`d_model=4, n_heads=2, T=3` 这种，小到能印在纸上，
  大到仍能暴露转置、广播、多头切分的结构。`d=1` 会把错误藏起来。
- 权重要"不漂亮"：别用全 1 或单位阵，那样算错了也看不出来。
- **每个印出来的数字都由脚本生成**，脚本直接输出表格源码，禁止手算誊抄。
- 中间结果全给：$QK^\top$、除以 $\sqrt{d_k}$ 之后、softmax 之后，逐步印。
- 给读者**可自查的检查点**："这一行加起来应当为 1"、"这个矩阵应当对称"。
- 每一步都标形状 $(B,T,C)$，公式与代码用同一套记号。

## 6. 数值纪律

1. 正文里每个数字都来自能重跑的脚本，不手算后直接写。
2. 引用程序输出**逐字复制**，连对齐空格一起，不要"整理"。
3. 收尾做一次**机器比对**：文档里所有代码块的行逐行 grep 真实 stdout，确认无一行对不上。
4. 每个关键结论配一条**路径不同源**的交叉验证（高精度重算 / 解析解 / 守恒量 /
   理论预言 vs 实测 / 多语言实现互校）。
5. 手算只用来形成预期；与程序冲突时先假设手算错了。
6. **结论必须和自己的表格一致。** 写完一段回头对一遍数字 —— "基本停住"却印着
   `5.28e-04 m/s`，这种自相矛盾只有逐行核对才抓得出来。
7. 扫参数时**避开互相整除的取值**（如 dt = 2e-2, 1e-2, ..., 2e-4）：量化误差会在
   每个点上逐位相同，扫出一条假的水平线。**结果"太干净"本身就是危险信号。**

详见 `references/verification.md`。

## 7. 图表纪律

- **图由代码生成**（matplotlib 或 TikZ 均可），源码入库，一条命令重建。
- **版面要算，不要试**：节点坐标、间距、文字宽度都显式算出来；TikZ 用具名节点 +
  `positioning` 明确相对距离，不要撒魔法坐标；matplotlib 显式设 `xlim/ylim`。
- **箭头必须有明确语义**：一种含义一种样式（数据流 / 依赖 / 梯度反传各不相同），
  超过一种就配图例。不要随手画箭头。
- **禁止文字重叠、禁止挤成一团**。空间不够就**减少内容或拆成两张图**，不要缩字号。
- **画完必须渲染成 PNG 亲眼看过**，逐项核对后才能放进教程。这一步不可跳过 ——
  压字、遮挡、被裁、坐标轴被离群点撑开，代码都不会报错。
- **示意图不能用被讲解的方法自己画自己**。例如讲线性插值时，"真实曲线"必须另跑一次
  细步长仿真，不能用 `np.interp` 从粗采样点插出来 —— 那画出来的是假曲线。
- 图内文字若用中文，必须显式指定字体（`Songti SC` 等）并设 `axes.unicode_minus=False`；
  没指定就会**静默**变豆腐块。拿不准就把文字放图注。

检查清单与实测踩过的坑见 `references/figures.md`。

## 8. AI 类内容特有

- **术语表**：开篇给中英对照。AI 中文译名极不统一，首次出现必带英文原词；
  `logits`/`token`/`embedding` 可不译，但要在表里说明。
- **版本注框**：模型 ID、API 形态、库接口变化极快。凡涉及具体模型/接口处标明
  「截至 YYYY-MM」与版本号 —— 这是 AI 教程半年就过期的主因。
- **张量形状**全程标注，公式与代码记号统一。
- 代码块必须可运行，附 `requirements.txt` 与 Python 版本，不要用伪 API。
- 讲清**为什么这样设计**而不只是"是什么"，这是教程与 API 文档的分界线。
